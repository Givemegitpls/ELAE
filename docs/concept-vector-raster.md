# Вектор vs растр: принцип разделения

Документ фиксирует правило, по которому в проекте разделяются операции над векторными
слоями и растровыми. Он нужен, чтобы не «размывать» вектор через промежуточные пиксели.

## Принцип

- **Векторный слой — только геометрия.** Правка точек, move/scale/rotate, заливка,
  клип, экспорт в SVG не имеют права зависеть от разрешения холста.
- **Растр — только там, где он и есть.** Растровые слои (PNG-подложки, bucket fill,
  трансформация картинки, экспорт PNG) работают с пикселями — это норма.
- **Два вида растеризации надо различать:**
  1. *Отрисовка* — `render.draw_stroke` рисует линии посэмплово с антиалиасингом, экран
     и PNG растеризуют всё. Это вывод, а не операция; он неизбежен.
  2. *Операция через пиксели* — когда результат векторного действия зависит от размеров
     холста (рендер в `QImage` размера документа, flood fill по вектору). Это запрещено,
     кроме единственного случая ниже.

## Единственное неизбежное исключение

`clip to below`, когда база клипа — **растровый слой** (или группа, содержащая растр).
Силуэт базы — это пиксельные данные; пересечение/вычитание по ней выразимо только
попиксельно. Такой клип остаётся буферным и документируется как исключение, а не как
общая практика.

## Правило для clip (реализовано)

Клип — операция над **альфой** базы, а не над её формой. Поэтому маска — пиксельная,
но она не «запекается» в документ:

- маска строится из содержимого базового узла (вектор, растр, будущие градиентные кисти —
  всё выразимо), обрезается по bbox содержимого (+1 px AA) и растеризуется **в разрешении
  цели** (`zoom × devicePixelRatio`, для экспорта — `scale`), с бюджетом `MAX_MASK_PIXELS`;
- маска кэшируется по сигнатуре геометрии/детей/растрового payload и переиспользуется для
  всей цепочки клипнутых сиблингов; живой штрих (`skip_stroke`) кэш обходит;
- база рисуется напрямую, в буфер уходит только клипнутый слой;
- `setClipPath` не используется для отрисовки: край двоичный (проверено: альфа `0 → 255`
  без промежуточных значений). Геометрический силуэт (`sai/silhouette.py`) нужен для SVG:
  `clipPath` при бинарной альфе базы, `<mask mask-type="alpha">` при частичной
  (градиенты/полупрозрачность), `mask-type="luminance"` с белым фоном и чёрной геометрией
  для `outside` в мягком случае.

Так «операция над вектором» не зависит от того, в каком разрешении её смотрят: кэш
разрешения-независим, маска строится на каждый масштаб заново, а альфа базы любого типа
поддерживается.

## Аудит текущего кода

| Место | Что делает | Вердикт |
|---|---|---|
| `canvas` — правка точек, transform векторного слоя | геометрия | ок |
| `canvas._fill_vector_at()` + `fill.figure_at()` | вектор: точки, прямой мост, `QPainterPath.contains` | ок |
| `fill.bucket_fill()` / `fill.region_mask()` | flood fill по пикселям; цель — растровый слой | ок |
| `io.export_svg()` | геометрия | ок |
| `render.draw_document()` → клип | база рендерится в `QImage` размера документа, затем `DestinationIn`/`DestinationOut` | нарушение, если база векторная; исключение, если база растровая |
| `io.export_png()` | растеризация всего документа | ок: это вывод |

## Состояние работ

Сделано:
1. `sai/silhouette.py` — границы содержимого (`node_bounds`), признак бинарной альфы
   (`is_opaque`), геометрический силуэт (`stroke_outline`/`outline_path`).
2. Маска клипа в разрешении цели + bbox + кэш (`render._clip_mask`, `_render_masked`);
   масштаб прокинут из `Canvas.paintEvent` и `io.export_png`.
3. SVG: `<clipPath>` для бинарных баз и `<mask>` для остальных; скрытая база эмитится
   внутрь определений, а не в тело документа.

Осталось (по мере роста кистей):
- учитывать будущие векторные кисти в `is_opaque` (сейчас критерий — `alpha == 255`);
- градиенты в SVG-масках (сейчас `<mask>` берёт альфу содержимого как есть).

## Открытые вопросы

- Обрезка/кэш буферов: по какому bbox считать (с учётом clip-цепочек).
- Группы как база клипа: силуэт = объединение силуэтов детей; смешанная группа
  (есть растр) уходит в пиксельный путь.
- Группы/UI: мультивыделение слоёв и drag&drop (правки в работе), после них —
  пересмотр панели слоёв.
